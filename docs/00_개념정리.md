# 개념정리 — SW 공급망 보안

> 본선 발표·질의응답 대비. 예시는 전부 내 레포 실제 스캔 결과(`02_실측기록.md`)에서 가져옴.

## 1. SW 공급망 (Software Supply Chain)
내 서비스는 내가 쓴 코드만으로 돌아가지 않는다. Spring Boot 하나를 쓰면 Tomcat, Jackson, Netty… 수십~수백 개 라이브러리가 따라 들어온다. 이 "남이 만든 부품들이 내 제품에 들어오는 경로" 전체가 공급망.
- 예: BuzzerBidder 서버 jar 안에 들어 있는 구성요소 **201개**. 내가 build.gradle에 직접 적은 건 그중 일부.
- 공급망 공격: 부품 하나에 구멍이 있으면(또는 누가 일부러 심으면) 그걸 쓰는 모든 제품이 위험. 대표 사례 Log4Shell(2021, log4j).

## 2. SBOM (Software Bill of Materials)
제품에 들어간 부품 목록표. "자재 명세서"의 SW 버전. 이름·버전·라이선스·출처를 기계가 읽을 수 있는 형식으로 기록.
- 표준 형식: **CycloneDX**(OWASP, 보안 중심), SPDX(리눅스재단, 라이선스 중심). 이번엔 CycloneDX 사용.
- 생성 도구: **syft** — jar나 폴더를 넣으면 SBOM을 뽑아줌.
- 왜 필요? 새 취약점이 터졌을 때 "우리 제품 중 그 부품 쓰는 게 어디 있지?"를 즉시 답하려고. SBOM이 없으면 레포를 하나하나 뒤져야 함.

## 3. CVE / GHSA
- **CVE**: 공개된 취약점 하나하나에 붙는 국제 식별번호. 예: `CVE-2021-44228`(Log4Shell).
- **GHSA**: GitHub이 붙이는 취약점 번호. CVE와 같은 건을 가리키는 경우가 많음.
- 취약점 DB: NVD(미국), OSV(구글, 오픈소스 패키지 중심), GitHub Advisory.
- **trivy**: SBOM 부품 목록을 이 DB들과 대조해서 "이 버전엔 이 CVE가 있다"를 찾아주는 스캐너.

## 4. 위험도 지표 3종 — 서로 다른 질문에 답한다

| 지표 | 질문 | 값 | 내 레포 예시 |
|---|---|---|---|
| **CVSS** | "최악의 경우 얼마나 심각한가?" | 0~10 → LOW/MEDIUM/HIGH/CRITICAL | BB의 tomcat-embed-core 10.1.49: CRITICAL 6건 |
| **EPSS** | "30일 안에 실제로 공격에 쓰일 확률은?" | 0~1 (확률) | 그 CRITICAL들의 EPSS: 0.012~0.017 (1%대) |
| **KEV** | "실제로 악용된 게 확인됐나?" | 예/아니오 (CISA 목록) | 두 서버 모두 해당 0건 |

핵심: **CVSS가 높다 ≠ 지금 급하다.** CVSS는 "가능한 피해 크기", EPSS/KEV는 "실제로 노려질 가능성". 그래서 CVSS 순으로만 줄 세우면 담당자가 덜 급한 것부터 고치게 된다.

## 5. 직접 의존성 / 전이 의존성
- **직접**: 내가 build.gradle에 직접 적은 것. 예: `spring-boot-starter-web`
- **전이(transitive)**: 직접 의존성이 또 끌고 온 것. 예: starter-web → tomcat-embed-core, jackson-databind
- 의미: 전이 의존성의 취약점은 보통 "그 라이브러리 버전만 따로 올리기"보다 **상위(Spring Boot) 버전을 올리는 게** 정석 조치. → 그래서 CVE 141건이 실제 조치로는 몇 개 안 될 수 있음 (`02_실측기록.md` Hypothesis 1).

## 6. Reachability (실제 사용 여부)
취약한 버전이 jar 안에 **들어 있는 것**과, 내 코드가 그 취약한 기능을 **실제로 쓰는 것**은 다르다.
- 레벨 1 (예선 프로토타입): 내 소스가 그 패키지를 import/사용하는가 (텍스트 검색 수준)
- 레벨 2 (확장): 함수 호출 그래프 — 내 코드에서 출발해 그 취약한 함수까지 실제 호출 경로가 있는가
- 한계: 전이 의존성은 내 코드가 직접 import 안 해도 프레임워크가 내부에서 씀(예: Tomcat은 import 안 해도 HTTP 요청마다 실행됨). 그래서 레벨 1은 "직접 안 쓴다 = 안전"으로 단정하면 안 되고, **우선순위를 낮추는 근거 중 하나**로만 써야 함.

## 7. 이 과제에서 에이전트가 하는 일 (한 줄 요약)
도구가 사실(부품 목록·CVE·EPSS·KEV·사용 흔적)을 모으고 → LLM이 그 사실을 근거로 "무엇부터, 어떻게 고칠지"를 판단·설명하고 → 그 판단이 근거와 맞는지 자동으로 검증한다.
